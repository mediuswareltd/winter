Guide ​

Multimodal retrieval over speech and keyframes so every answer is cited by timestamp.

Winter

Chat with your videos.
Multimodal retrieval over speech and keyframes, with every answer cited by timestamp.

Ask a question about hours of video and get a grounded answer in seconds. Every claim links to the exact moment it came from: click a citation and the player jumps there.

It searches what was said (Whisper transcripts) and what was shown (keyframes searched with CLIP and passed to Claude as images), so it can answer "when do they show the architecture diagram?" as well as "what did they say about pricing?".

You:    How much did API latency improve after the caching work?
Answer: Average API latency dropped from 320 ms to 90 ms after engineering shipped a
        Redis caching layer in August [0:13] [0:28].
                                       ^ click: video seeks to 0:13

Use cases: searching meeting and webinar recordings · course and lecture Q&A · searching support or training video libraries · reviewing research interviews · compliance review of recorded calls · internal knowledge bases built from Loom/Zoom recordings.

Features ​

Any video sourceDrag-and-drop upload (mp4, mov, mkv, webm, mp3, wav…) or paste a YouTube URL
Timestamped transcriptsfaster-whisper speech-to-text with voice-activity filtering; runs on CPU, faster on a GPU, 90+ languages
Visual understandingScene-change keyframe detection (OpenCV) plus CLIP image embeddings, so text queries find matching frames
Hybrid retrievalDense embeddings (BGE) and BM25 keyword search, merged with Reciprocal Rank Fusion
Multimodal answersTranscript excerpts and the matching keyframes go to Claude, which answers with inline [n] citations
Clickable citationsEach citation is a timestamp chip; clicking it seeks the player. Source cards show the frame and excerpt
StreamingAnswers stream token by token over Server-Sent Events
Works without an API keyUses a local model through Ollama when no key is set; with no model at all, it returns the best-matching moments, so search still works
Scoped searchSearch the whole library or a single video; follow-up questions keep conversation context
Production basicsBackground ingest queue with live progress, resume after restart, Docker image, tests

Architecture ​

mermaid
flowchart LR
    subgraph Ingest
        A[Video file / YouTube URL] --> B[ffmpeg: 16 kHz mono audio]
        B --> C[faster-whisper<br/>timestamped segments]
        C --> D[Overlapping ~45 s chunks]
        D --> E[BGE text embeddings]
        A --> F[OpenCV scene-change<br/>keyframes]
        F --> G[CLIP image embeddings]
    end
    E & G --> H[(SQLite + vectors)]
    subgraph Query
        Q[Question] --> R1[Dense search]
        Q --> R2[BM25 search]
        Q --> R3[CLIP text→image search]
        R1 & R2 --> RRF[Reciprocal Rank Fusion]
        RRF & R3 --> S[Sources + keyframes]
        S --> L[Claude: cited answer]
        L --> UI[Web UI: streaming answer,<br/>timestamp chips → player seek]
    end
    H --> R1 & R2 & R3

Design decisions ​

  • Chunking on segment boundaries. Chunks are about 45 s windows with about 10 s of overlap, and they never split a Whisper segment. Every citation starts at a real sentence boundary, and an answer that spans two chunks can still be retrieved from one of them.
  • Hybrid search, fused by rank. Dense embeddings handle paraphrases ("how fast is it now"). BM25 handles exact terms that embeddings blur: product names, error codes, numbers. RRF combines the two by rank, so the scores never need calibrating against each other.
  • Two kinds of visual evidence. CLIP finds frames that match the question even when nothing is being said, such as a slide or a demo. Claude then receives the actual keyframe images, so it can read slide text, code on screen and diagrams.
  • Exact vector search on NumPy, no vector database. A brute-force cosine search over an in-memory matrix is exact, needs no extra service, and stays fast up to a few hundred thousand chunks (roughly a few thousand hours of video). VectorIndex in store.py is the one class to replace if you move to pgvector, Qdrant or LanceDB.
  • Prompting for grounded answers. The model must cite every claim, say when the videos don't cover a question instead of guessing, and allow for speech-recognition misspellings.

Quick start ​

Docker (recommended) ​

Needs only Docker (Docker Desktop on Windows/macOS).

bash
git clone https://github.com/<you>/winter.git
cd winter
docker compose up -d --build

Open http://localhost:8000. That one command:

  • builds the Winter image (Python, ffmpeg, CPU PyTorch)
  • starts Ollama and pulls a small local model (qwen2.5:3b, ~1.9 GB), so you can chat with no API key
  • keeps your videos, index and downloaded models in Docker volumes, so restarts are instant

The first start takes a few minutes for the downloads. Follow along with docker compose logs -f. The header shows LOCAL qwen2.5:3b once the model is ready; until then, answers list the matching passages.

Use Claude instead (better answers, and it can read the keyframes):

bash
cp .env.example .env          # set ANTHROPIC_API_KEY=...
docker compose up -d          # Claude is used whenever a key is set

Common tweaks, all set in .env:

WantSet
A different portWINTER_PORT=8080
A bigger/smaller local modelVIDEORAG_OLLAMA_MODEL=llama3.2:3b (or qwen2.5:7b with 16 GB+ RAM)
No local model at allrun docker compose up -d winter (starts only the app)
NVIDIA GPU for the local modeldocker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d

Day to day:

bash
docker compose stop                  # stop, keep everything
docker compose up -d --build         # update after a git pull
docker compose exec winter python -m videorag list    # CLI inside the container
docker compose down -v               # remove containers AND all data/models

Without Docker ​

Requirements: Python 3.10+ and ffmpeg on PATH.

bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e .

cp .env.example .env          # optional: add your ANTHROPIC_API_KEY
winter serve                  # open http://127.0.0.1:8000

The Whisper, BGE and CLIP models (about 1 GB in total) download on first use and are cached afterwards.

For answers without an API key, install Ollama and run ollama pull qwen2.5:3b. Winter detects the running model automatically.

How answers are generated ​

SetupWho writes the answer
ANTHROPIC_API_KEY setClaude, using transcripts and keyframe images
No key, Ollama running with the model pulledThe local model, using transcripts only
NeitherNo generated answer; Winter lists the best-matching moments

Force one with VIDEORAG_LLM=claude|ollama|none. A 3B local model is fine for factual lookups but cites less consistently than Claude.

CLI ​

bash
winter ingest talk.mp4 "https://www.youtube.com/watch?v=..."
winter list
winter search "rate limiting" -k 5
winter ask "What did they recommend for rate limiting?"

VIDEORAG_CLAUDE_EFFORTmediumlow is faster and cheaper; high reasons more deeply

VIDEORAG_SCENE_THRESHOLD0.35Lower it to capture more keyframes

Project layout ​

videorag/
  media.py        ffmpeg/ffprobe helpers, yt-dlp download
  transcribe.py   faster-whisper speech-to-text
  frames.py       scene-change keyframe extraction
  chunking.py     segment → overlapping chunk windows
  embeddings.py   BGE text and CLIP image embeddings
  store.py        SQLite persistence + in-memory vector index
  retrieval.py    hybrid search (dense + BM25 + RRF) and visual search
  llm.py          prompt construction; streaming answers from Claude or Ollama
  pipeline.py     ingest orchestration with progress reporting
  api.py          FastAPI app (REST + SSE) serving the web UI
  cli.py          command-line interface
  web/            dependency-free HTML/CSS/JS front end
tests/            unit and API tests (no model downloads needed)

Development ​

bash
pip install -e ".[dev]"
pytest -q
ruff check . && ruff format --check .

The tests use stub embeddings, so they run in a few seconds with no GPU, models or API key.
